## Run

This project reads the existing CSVs in `shopfast-kit/data` with DuckDB. It does not need a Docker service.

From the repository root in PowerShell, activate the local Python environment:

```powershell
.\.venv\Scripts\Activate.ps1
cd CTP3\shopfast_dbt
dbt build --profiles-dir .
dbt docs generate --profiles-dir .
python check_governance.py
python export_dictionary.py
```

On a new computer, first run `python -m venv .venv`, activate it, and run `python -m pip install -r CTP3/requirements.txt` from the repository root.

To view the catalog, run `dbt docs serve --profiles-dir . --port 8080` and open [localhost:8080](http://localhost:8080). Search for `pii` with the **Tags** box selected to find the models containing personal data. Click a column row to see its classification and full definition.

## Definition choices

- The company uses 12 calendar months for **active customer**, with non-cancelled orders from registered accounts. Sales can use **recently active customer (6 months)** as a separate label.
- **Churned customer** means a previous buyer with no qualifying order in the 12-month window. Never-buyers do not count as churned. The rule uses known dates; undated orders need review.
- **Net revenue** is `(order total - refunds) / 1.20`, rounded to 2 decimals per order. The lab assumes 20% VAT and keeps shipping in the order total. Sales uses **sales revenue including VAT** before dividing by 1.20.

The glossary decisions are approved for this class exercise. Sales and Finance disagreed about the time window and VAT; Finance also explicitly excluded cancelled orders. The separate Sales labels keep those meanings clear.

I changed `dim_customers.last_order_date` to ignore cancelled orders and dates after the build date. Rebuild it for a new reporting date. The other lifetime metrics still include all linked orders.
The starter revenue model uses order totals, not captured cash. Missing dates, orphan customer IDs and other source errors are documented rather than silently corrected.
